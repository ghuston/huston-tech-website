# Form to the app, and hosting wording: plan

Run: "Form to the app, and hosting wording" (live-site change, 09 doc items W1 and W3, 2026-11-24). Brief approved by

## Goal

- **PR A (W1), `feat/form-to-pipeline`:** the contact Worker sends each submission to the Pipeline app
  (`https://pipeline.hustonlogic.com/intake`) server to server. The Sheet stays as the fallback. Code with tests.
- **PR B (W3), `feat/hosting-wording`:** every line that says client accounts, hosting or logins are in the client's
  name is rewritten to the 2026-11-24 hosting decision. Copy only. No auto-merge: Grant approves the wording on the
  preview first.

Never remove a test, weaken an assertion, lower a threshold or change which checks are required.

## Source

Pipeline README, "Connect a website form" (`huston-logic/pipeline`): `POST /intake`, header `X-Intake-Secret`; `name`,
`email`, `message` required; `phone`, `business`, `source` optional; other fields ignored; body at most 16 KB, `message`
at most 5,000 characters; `201` added, `200` repeat (same email and message within 10 minutes); anything else is a
failure (400, 401, 405, 413, 415, 429, 503). Unset secret on the app side answers 503.

## PR A tasks (TDD: tests first, watch them fail, then code; `npm run check:fast` before each commit)

1. **Tests.** In `worker/contact.test.ts` add a `pipeline` route and responder and tests: no secret means no call to
   the app and the Sheet is used (as today); with the secret the app gets the right URL, header and JSON, the Sheet is
   not written, the email says "Saved to: the Pipeline app"; app 500 is retried once then falls back to the Sheet; app
   401 falls back with no retry; app unreachable falls back; app and Sheet fail but email works is still success and
   the email says to add it by hand; all three fail is 502; app saved and email failed is still success; preview mode
   never calls the app; the secret never appears in a log line; the composed message is labelled, skips empty fields
   and stays within 5,000 characters.
2. **`worker/intake.ts`.** `intakeMessage(submission)` and `sendToPipeline(secret, submission)`: one POST, 8 s
   timeout, one retry on 429 or 5xx, true on any 2xx. Logs fixed event names and status codes only.
3. **`worker/env.ts`, `worker/messages.ts`, `worker/contact.ts`.** Add optional `INTAKE_SECRET`. Order: app first (when
   the secret is set and the mode is production), then the Sheet only if the app did not take it, then the email, which
   always sends and says where the submission was saved. Success if the app, the Sheet or the email got it.
4. **`wrangler.jsonc`.** Rate limiter ids 1001 to 2101 (production) and 1002 to 2102 (preview). `INTAKE_SECRET` is not
   added to `secrets.required`. It is an "ask" file: if the edit is refused, queue it under Needs Grant.
5. **Docs.** README "Contact form" section and the secrets table (INTAKE_SECRET, optional until Grant says so);
   AGENTS.md Contact form line; STATUS.md Needs Grant gets the exact commands. `docs/pipeline/` is a copy of the
   template's handbook, so it is left alone and named in the PR.
6. **Check and PR.** `npm run check`, then review-code and review-security once on the branch, then open PR A and
   enable auto-merge (`gh pr merge <n> --auto --squash`, the form the hook allows).

## PR B tasks

7. **Find.** A Haiku subagent greps `src/` and `worker/` for client-name wording ("your name", "your accounts", "own
