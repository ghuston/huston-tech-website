# The contact form Worker

The one piece of server code in the pipeline. `POST /api/contact` runs a small Cloudflare Worker
that checks the request, verifies Turnstile, writes a row to a Google Sheet, emails the owner and
sends the visitor a plain-text automatic reply. Everything here was read from `worker/`,
`src/`, `wrangler.jsonc`, the README and the PR history on 2026-11-15. Secrets appear by **name
only**.

Back to the [map](./README.md). Deploy side: [gate3-deploy-ops.md](./gate3-deploy-ops.md).
Setting it up for a client: [client-onboarding-checklist.md](./client-onboarding-checklist.md).

## Architecture

```
Browser (/contact)                               Cloudflare                      Outside
------------------                               ----------                      -------
src/components/hl/ContactForm.tsx  --POST JSON-->  worker/contact.ts
  validateContact() (shared)                        resolveMode()        (env.ts)
  useTurnstile.ts (loads Turnstile                 same-origin, JSON, 16 KB
    on first focus, action "contact")              CONTACT_RATE_LIMIT binding (5/min/IP)
  saveHandoff() -> sessionStorage                  honeypot (company_fax)
  router.push("/contact/thanks")                   validateContact() (shared)
                                                   verifyTurnstile()    (turnstile.ts) --> challenges.cloudflare.com/turnstile/v0/siteverify
                                                   appendRow()          (sheets.ts)    --> oauth2.googleapis.com/token, sheets.googleapis.com
                                                   sendEmail() x2       (email.ts)     --> api.resend.com/emails
                                                   log()  fixed event names only
```

Files:

| File | Role |
|---|---|
| `worker/contact.ts` | The handler: routing, every check in order, the three outside calls, the JSON answer |
| `worker/env.ts` | `ContactEnv` (the bindings), `resolveMode()`, `log()`, `TIMEOUT_MS` (8000), `retryable()` |
| `worker/turnstile.ts` | Server-side Turnstile check; tells a visitor failure from a configuration failure |
| `worker/sheets.ts` | Service-account JWT signed with Web Crypto (RS256), token exchange with a cache, append with RAW input and a formula guard, one retry |
| `worker/email.ts` | One Resend call, plain text only, idempotency key, one retry |
| `worker/messages.ts` | The notification email, the automatic reply and the Sheet row, built from the content modules |
| `worker/contact.test.ts` | 36 tests on Node's built-in runner with `fetch` replaced by a recorder; a throwaway RSA key stands in for the service account |
| `worker/tsconfig.json` | ES2024, `moduleResolution: Bundler`, `erasableSyntaxOnly`, `allowImportingTsExtensions`; includes only the five shared `src/` modules |
| `worker/worker-configuration.d.ts` | Generated by `npx wrangler types worker/worker-configuration.d.ts`; regenerate after changing `wrangler.jsonc` |
| `src/components/hl/ContactForm.tsx` | The client component (`"use client"`), the only form on the site |
| `src/components/hl/useTurnstile.ts` | Loads the Turnstile script on first focus, renders it `interaction-only`, hands out one-use tokens |
| `src/lib/contact-handoff.ts` | `sessionStorage` handoff of the first name and auto-reply result to `/contact/thanks` |
| `src/lib/contact-validation.ts` | `validateContact()`: the one set of rules the form and the Worker both apply |
| `src/lib/first-name.ts` | First name for the greeting; a name that is not a name gets no greeting name |
| `src/content/contact-fields.ts` | Option values, field limits, the honeypot field name |
| `src/content/auto-reply.ts` | The B7b automatic reply text |
| `src/content/providers.ts` | `email`, `schedulerUrl`, `linkedInUrl`, `turnstileSiteKey` (all public values) |

The Worker may import only import-free modules from `src/` (`AGENTS.md`): `content/contact-fields.ts`,
`content/auto-reply.ts`, `content/providers.ts`, `lib/contact-validation.ts`, `lib/first-name.ts`,
with explicit `.ts` extensions, so the form and the Worker share one set of rules. It never imports
`site.ts`, which reads `process.env`. It uses **no libraries**: Web Crypto for the Google JWT, `fetch`
for Turnstile, Resend and Sheets.

## The request pipeline (from `worker/contact.ts`, in order)

Every answer is JSON with `cache-control: no-store`, `x-content-type-options: nosniff`,
`referrer-policy: strict-origin-when-cross-origin`, `cross-origin-resource-policy: same-origin` and
`content-security-policy: default-src 'none'; frame-ancestors 'none'`. The body is either
`{ ok: true, autoReply: boolean }` or `{ ok: false, error, fields? }` where `error` is one of
`invalid`, `rejected`, `rate_limited`, `failed`. The form maps those four words to the three approved
B7 messages (`notVerified`, `rateLimited`, `failed`) or to per-field errors.

| # | Check | On failure | Log event |
|---|---|---|---|
| 0 | Path is `/api/contact` and method is `POST` | 404 `not_found` / 405 `method_not_allowed` with `allow: POST` | |
| 1 | `resolveMode(SITE_ENV, hostname)` returns a mode | 500 `failed` | `config_invalid_mode` |
| 2 | `origin` header equals the request origin, and `sec-fetch-site` is absent or `same-origin` | 403 `rejected` | `rejected_origin` |
| 3 | `content-type` starts with `application/json` | 415 `rejected` | |
| 4 | `content-length` and the streamed body are at most 16 KB | 413 `rejected` | |
| 5 | Body parses as a JSON object whose keys are all in the allowed set (the nine contact keys, `company_fax`, `turnstileToken`) | 400 `rejected` | |
| 6 | `CONTACT_RATE_LIMIT.limit({ key: cf-connecting-ip })` succeeds (5 per 60 s) | 429 `rate_limited` | `rate_limited` (or `rate_limit_binding_missing` if the binding is absent; the request continues) |
| 7 | The honeypot field `company_fax` is empty | 400 `rejected` (an honest error, never a pretend success) | `honeypot_filled` |
| 8 | `validateContact()` passes | 400 `rejected` if malformed (a value no person could enter through the form), else 400 `invalid` with `fields` | |
| 9 | `TURNSTILE_SECRET_KEY` is set | 502 `failed` (our fault, not the visitor's) | `turnstile_config_missing` |
| 10 | `turnstileToken` is a non-empty string of at most 2048 characters | 403 `rejected` | `turnstile_token_missing` |
| 11 | siteverify reachable and the secret accepted | 502 `failed` | `turnstile_unavailable` with Cloudflare's codes |
| 12 | siteverify `success`, and (outside development) `hostname` equals the request hostname and `action` equals `contact` | 403 `rejected` | `turnstile_failed` with `reason` `not_success`, `hostname_mismatch` or `action_mismatch` |
| 13 | development mode stops here | 200 `{ ok: true, autoReply: true }` | `dry_run` |
| 14 | `appendRow()` to the `Submissions` tab (production) or `Preview` tab | continues; the email says "Sheet: NOT saved - add this one by hand" | `sheet_*` events |
| 15 | `sendEmail()` the notification to the site address, Reply-To the visitor | continues | `email_failed` / `email_unreachable` with `kind: notify` |
| 16 | At least one of 14 and 15 succeeded | 502 `failed`, and no automatic reply | `capture_failed`; or `notify_failed_sheet_saved` when only the email failed |
| 17 | `sendEmail()` the automatic reply to the visitor (production) or to the site address (preview) | `autoReply: false` in a 200 answer | `auto_reply_failed` |

The Sheet goes first so the email to the owner can say whether the row was saved. The idempotency
keys are `<uuid>-notify` and `<uuid>-reply`, so a retry can never send the same email twice. Each
outside call gives up after 8 seconds and retries once on 429 or 5xx (and once on a 401 from Sheets,
after dropping the cached access token).

### Modes (`worker/env.ts`, `resolveMode`)

| `SITE_ENV` | Hostname | Mode | Behaviour |
|---|---|---|---|
| `development` | `localhost`, `127.0.0.1`, `[::1]` | development | Turnstile checked with Cloudflare's test keys (hostname and action not enforced), then nothing is emailed or written; one `dry_run` log line |
| `development` | anything else | **null** (500) | A stray setting can never turn the live form into one that sends nothing |
| `preview` | any | preview | Rows go to the `Preview` tab, every subject starts with `[Preview]`, the automatic reply goes to the site's own address with a subject naming who it would have gone to |
| `production` | `*.workers.dev` other than `huston-site.*` | preview | A branch preview is a preview even if its vars say otherwise |
| `production` | anything else | production | The live site |
| anything else | any | **null** (500) | Fails closed |

### What the visitor sees (`ContactForm.tsx`, `contact-handoff.ts`)

- Success only when the note reached the owner (a Sheet row or the email). The form then stores the
  first name and whether the automatic reply went out in `sessionStorage` (keys
  `hl-contact-first-name`, `hl-contact-auto-reply`), never the URL, and moves to `/contact/thanks`,
  which says "Got it, thanks {name}." If the automatic reply failed, the thanks page says so. If
  storage is blocked, the thanks page shows its plain version.
- Every failure keeps the visitor's answers and shows one of the three B7 send errors in a
  `role="status"` region; the Turnstile widget is reset because tokens work once.
- `method="post"`, no `action`, `noValidate`: without JavaScript nothing is sent and nothing lands in
  the URL.
- A missing site key (`providers.turnstileSiteKey` null) is an honest `failed` error; the launch gate
  fails on the null anyway.
- `?topic=website|workflow|partner` prefills the need or shows the partner variant; the form reads it
  in the browser (a static page cannot read the query at build time), inside `Suspense` with the
  unselected form as the fallback.

### Logs

Workers Logs is on, invocation logs are off (`wrangler.jsonc`). The Worker logs one JSON line per
event with fixed event names, status codes, attempt numbers and Cloudflare's fixed error codes only,
never names, emails, messages, IP addresses or keys. The full set of event names, from the source:
`config_invalid_mode`, `rejected_origin`, `rate_limited`, `rate_limit_binding_missing`,
`honeypot_filled`, `turnstile_config_missing`, `turnstile_token_missing`, `turnstile_unavailable`,
`turnstile_failed`, `turnstile_http_error`, `turnstile_unreachable`, `dry_run`,
`sheet_config_missing`, `sheet_token_failed`, `sheet_token_unreachable`, `sheet_append_failed`,
`sheet_unreachable`, `email_config_missing`, `email_failed`, `email_unreachable`, `capture_failed`,
`notify_failed_sheet_saved`, `auto_reply_failed`.

## Secrets by name

Four Worker secrets. `wrangler.jsonc` lists the names under `secrets.required`, so a deploy fails
while one is missing. Values exist only in Cloudflare, set by the owner from their own terminal in
the repo folder; never in the repo, chat or logs. Each `secret put` asks for the value with hidden
input.

| Name | What the value is |
|---|---|
| `RESEND_API_KEY` | A Resend API key with "Sending access" scoped to the sending domain only |
| `TURNSTILE_SECRET_KEY` | The Turnstile widget's secret key |
| `GOOGLE_SERVICE_ACCOUNT_KEY` | The whole service-account JSON key file (the Worker reads `client_email` and `private_key` from it) |
| `GOOGLE_SHEET_ID` | The Sheet ID (between `/d/` and `/edit` in its URL) |


### Local development

`wrangler dev` needs the four names to exist but uses none of their values in development mode. The
README's command and the `worker` entry in the untracked `.claude/launch.json` pass `SITE_ENV`,
Cloudflare's published always-pass Turnstile test secret, and placeholder text for the other three
with `--var`, on port 4823 bound to `localhost`:

```bash
npm run build
```

then `npx wrangler dev --port 4823 --ip localhost --var SITE_ENV:development --var TURNSTILE_SECRET_KEY:<cloudflare-always-pass-test-secret> --var RESEND_API_KEY:x --var GOOGLE_SERVICE_ACCOUNT_KEY:x --var GOOGLE_SHEET_ID:x`
(the README has it with the published test value filled in). The form on a local host uses
Cloudflare's always-pass test **site** key automatically (`useTurnstile.ts`, `LOCAL_TEST_SITE_KEY`),
so the whole flow runs without a real widget. Cloudflare also publishes an always-fail test secret
for seeing the "couldn't verify" error. These are documented test values, not secrets. A `.dev.vars`
file would also work and is git-ignored, but the rule is never to put real keys in it.

The hooks and `settings.json` deny the agent any read of `.dev.vars`, `.env*` (except
`.env.example`) and `secrets/**`; `git add` of them is blocked too.

## Turnstile

- **Widget** (README; dashboard, **UNVERIFIED**): Cloudflare dashboard, Turnstile, widget named
  `huston-site contact`, Managed mode. Hostnames: the apex (covers its subdomains, so `www.` too
  once added) and the account's `<account>.workers.dev` (meant to cover the production and preview
  workers.dev hosts; error 110200 on a preview means it does not).
- **Site key** is public by design and lives in `src/content/providers.ts` (`turnstileSiteKey`). The
  **secret key** is the Worker secret `TURNSTILE_SECRET_KEY`.
- **Client** (`useTurnstile.ts`): the script `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit`
  loads only when the visitor first focuses the form (or submits), so page load never fetches a
  third-party script. It renders with `action: "contact"`, `appearance: "interaction-only"` (invisible
  unless Cloudflare needs a click), `refresh-expired: auto`, `response-field: false`. `getToken()`
  waits up to 60 seconds for a token. Tokens work once, so the widget is reset after every attempt
  that did not leave the page.
- **Server** (`turnstile.ts`): POSTs `secret`, `response`, `remoteip` and a random
  `idempotency_key` to siteverify. `missing-input-secret` and `invalid-input-secret` are
  configuration errors (502, our fault); every other failure is the visitor's (403). Outside
  development, `hostname` must equal the request hostname and `action` must be `contact`, which stops
  a token minted on another site or widget from being replayed here.
- **CSP** (`public/_headers`): `https://challenges.cloudflare.com` is in `script-src` and
  `frame-src` only. `connect-src` and `form-action` stay `'self'` because the form posts to the
  same-origin Worker.

## DNS for Google Workspace plus Resend

From the README "Accounts and DNS" (records as added on 2026-11-15) and commit `3eafc71`. The domain's
mail is split: Google Workspace owns the mailbox and the root domain's mail records; Resend sends
from the same address but through its own subdomain records, so the two never touch.

| Owner | Type | Name | Content | Notes |
|---|---|---|---|---|
| Google Workspace | MX | root | Google's 5 MX records | The only MX records on the root (owner-confirmed 2026-11-15) |
| Google Workspace | TXT | root | `v=spf1 include:_spf.google.com ~all` | The only SPF record on the root. **Never add Resend to it.** |
| Google Workspace | TXT | `google._domainkey` | Google's DKIM key | |
| Resend (Forge) | TXT | `resend._domainkey` | DKIM key (value from Resend) | Aligned DKIM on the root domain is what makes DMARC pass for Resend mail |
| Resend (Forge) | CNAME | `send` | `send.forge.rmta.net` | Return-Path host. **No MX and no SPF TXT on `send`**: a CNAME cannot share its name with other records, and Resend serves the bounce records through the CNAME target |
| Resend (Forge) | CNAME | `rsend` | `rsend.forge.rmta.net` | |
| Cloudflare DMARC Management | TXT | `_dmarc` | `v=DMARC1; p=none; rua=<Cloudflare reporting address>` | Created by Cloudflare's DMARC Management feature (owner-confirmed 2026-11-15). Policy is `p=none` (monitor only) for now; the plan is `p=quarantine` after 2 to 4 weeks of clean reports. The reporting address is Cloudflare's and is not recorded here |
| Leftover | TXT | `cf2024-1._domainkey` | Cloudflare Email Routing's old DKIM key | Harmless; left over from the Email Routing setup below (owner-confirmed 2026-11-15) |

All Resend records are "DNS only" (grey cloud, not proxied). Open and click tracking stay off in
Resend. SPF for Resend mail passes on `send.<domain>` and aligns under DMARC's relaxed alignment;
DKIM aligns exactly. The Launch checklist requires SPF, DKIM and DMARC to all show PASS in Gmail's
"Show original" for both the notification and the automatic reply.

**Email Routing versus Workspace MX (owner-confirmed 2026-11-15).** Cloudflare Email Routing and
Google Workspace both need the root MX records, so only one of them can receive mail for the domain.
On this domain Workspace replaced Email Routing. The steps taken, in order:

1. Cloudflare dashboard, Email, Email Routing, Settings, **Disable** Email Routing.
2. Remove Email Routing's `route*.mx.cloudflare.net` MX records from the root.
3. Remove Email Routing's SPF (`include:_spf.mx.cloudflare.net`) from the root, so the root has no
   second SPF record.
4. Add Google's 5 MX records on the root.
5. Add the single root SPF `v=spf1 include:_spf.google.com ~all`.
6. Add Google's DKIM at `google._domainkey` (from the Workspace admin console).

The leftover `cf2024-1._domainkey` TXT from Email Routing is harmless and was left in place. For a
client domain that will use Workspace from the start, simply never enable Email Routing.

## The Google side

From the README and `worker/sheets.ts`:

- **Google Cloud project** `huston-logic-site`, with the **Google Sheets API** enabled.
- **Service account** `contact-form-writer` with **no project roles**. Its JSON key is the secret
  `GOOGLE_SERVICE_ACCOUNT_KEY`. The Worker signs a JWT (`iss` = `client_email`, `scope` =
  `https://www.googleapis.com/auth/spreadsheets`, `aud` = `https://oauth2.googleapis.com/token`,
  one hour) with the key's `private_key` through `crypto.subtle` (RSASSA-PKCS1-v1_5, SHA-256),
  exchanges it for an access token (cached until 60 seconds before expiry), and calls
  `spreadsheets/<id>/values/<tab>!A:K:append?valueInputOption=RAW&insertDataOption=INSERT_ROWS`.
- **The Sheet** is shared as Editor with the service account **only**. Tabs `Submissions` and
  `Preview`, header row `Received (UTC) | Need | Topic | Name | Email | Business | Message | Tools | Website | Source | Mode`.
  `valueInputOption=RAW` stops Sheets from parsing formulas, and `safeCell()` still prefixes any cell
  starting with `=`, `+`, `-`, `@`, tab or carriage return with `'` (OWASP CSV-injection guidance),
  for the day the sheet is exported and opened elsewhere.
- **Weekly check** (README): once a week, open the `Submissions` tab and make sure every row has had
  a reply; a row with no email in the inbox means the notification failed
  (`notify_failed_sheet_saved`).

**Service-account keys blocked by the Workspace organisation policy (owner-confirmed 2026-11-15).**
Creating a new Google Workspace also creates a Google Cloud organisation with Google's
Secure-by-Default policies, including `iam.managed.disableServiceAccountKeyCreation`, which blocks
creating service-account keys. The fix used, project-only:

1. The Workspace **super admin** grants themselves the **Organization Policy Administrator** role at
   the **organisation** level.
2. In the Cloud project: IAM & Admin, **Organization Policies**, open that policy, **Manage policy**,
   **Override parent's policy**, set enforcement to **Off**, save.
3. "Create new key" on the service account now works.

Only the one project is overridden; the organisation default stays on. See the
[checklist](./client-onboarding-checklist.md).

## Resend

- **Why Resend rather than Postmark** (owner-confirmed 2026-11-15; the plan, E6, allowed either):
  Resend's free tier covers this volume, it has a simple REST API usable with plain `fetch` (so no
  SDK dependency in the Worker), and Cloudflare's dashboard can configure its DNS records
  automatically.
- Domain verified through the Forge records above. The API key has "Sending access" for the one
  domain only (README).
- Both emails are **plain text** (`text` only, never `html`), from `<Business> <site address>`,
  through `POST https://api.resend.com/emails` with an `idempotency-key` header (`email.ts`).
- Notification: subject `New note: <need> from <name>` (capped at 120 characters, `[Preview] `
  prefix outside production), Reply-To the visitor, every field labelled, plus `Sheet: saved` or
  `Sheet: NOT saved - add this one by hand`, and `Mode: <mode>` outside production.
- Automatic reply (B7b, `src/content/auto-reply.ts`): greeting with the first name, or the
  no-name greeting when the name does not look like a name (so a spammer cannot put text in it);
  the scheduler link from `providers.schedulerUrl`, falling back to `<origin>/contact#book`.

## Failure behaviour

| Sheet | Email to the owner | Visitor sees | Logged |
|---|---|---|---|
| saved | sent | Success | |
| failed | sent | Success; the email says "Sheet: NOT saved - add this one by hand" | `sheet_*` |
| saved | failed | Success (the row is real) | `notify_failed_sheet_saved` (covered by the weekly Sheet check) |
| failed | failed | "Something broke on my end..." (502), no automatic reply | `capture_failed` |
| any | any, auto-reply failed | Success, thanks page says the automatic reply did not go out | `auto_reply_failed` |

Turnstile: "That didn't go through" (403) is the visitor's check failing; a missing or refused
`TURNSTILE_SECRET_KEY` or an unreachable siteverify is "Something broke on my end..." (502). Commit
`1f1fa8d` ("report a missing or refused Turnstile secret as our failure") made that split, which is
also why the preview-secrets gotcha was visible: a preview without the secret showed the owner's
error, not the visitor's.

## Tests

### `worker/contact.test.ts` (36 tests, `npm run test:worker`, part of `npm run check` and of CI's `check` job)

Node's built-in runner. `fetch` is replaced by a recorder that routes by URL (`siteverify`, `token`,
`sheets`, `notify`, `reply`) and `console.log` is captured, so nothing reaches Turnstile, Resend or
Google. A throwaway RSA key pair stands in for the service account. Groups and cases, from the
`describe`/`test` names:

- **routing**: other paths are 404 and other methods are 405.
- **requests rejected before any outside call**: wrong origin, wrong content type, oversize body,
  bad JSON, unknown keys, honeypot filled, malformed values; "field errors name the fields"; "rate
  limited"; "an unknown SITE_ENV fails closed".
- **Turnstile**: a failed check sends nothing; a token from another hostname or action is refused; a
  missing secret is our failure (502) and calls nothing; a secret Cloudflare refuses, or an
  unreachable siteverify, is our failure (502); the secret, token and IP go to siteverify.
- **a good submission in production**: saves the row, emails the owner and sends the B7b
  auto-reply, all plain text; the partner variant needs no need field; a name that isn't a name gets
  no greeting name; the service-account JWT is RS256 and verifies with the public key.
- **preview mode**: mail goes only to the site's address and the row goes to the `Preview` tab; a
  workers.dev branch host counts as a preview even if `SITE_ENV` says production.
- **development mode**: verifies Turnstile with test keys, then sends nothing.
- **failures**: Sheet fails / email works; Sheet works / email fails; both fail (502, no auto-reply);
  missing secrets fail cleanly with 502, never a success; auto-reply fails (success with
  `autoReply: false`); retries reuse the idempotency key.
- **shared helpers**: `firstName`, `safeCell`, `validateContact` cleans text the way the form
  expects.

### Hand tests on a preview (PR 51's test plan)

Submit with your own address: you land on "Got it, thanks <name>."; the site inbox gets
`[Preview] New note...` (Reply goes to your address) and `[Preview → would go to ...] Got it, thanks`;
the `Preview` tab gets a row and `Submissions` does not. In Gmail, "Show original": SPF, DKIM and
DMARC all PASS. Turnstile works on the `workers.dev` host (error 110200 means the hostname is not
covered). Try `?topic=partner`, a missing field, and six quick submits (the sixth gets the
rate-limit message). Then on a phone: the form, the widget if it appears, the thanks page.
